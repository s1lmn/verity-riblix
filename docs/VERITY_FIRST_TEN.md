# Первые десять Verity

Пользователь уточнил образ: простой гладкий шарик с двумя чёрными овальными глазами и улыбкой по присланному референсу. Ушки, конечности и прежние условные существа отменены. Цвета должны быть яркими, а движения — выразительными; особые уровни допускают новые лица, светящиеся глаза и эффекты. Сейчас создаются только уровни 1–10, остальные — после совместной доводки.

Карту v5 пользователь сообщил как проверенную и подходящую. Это пользовательская проверка; автоматические тесты 16 игроков и FPS агентом не проводились. Геометрия карты, домов и интерьера в этой задаче не меняется. Старые картины с условным маскотом пока не переделаны; их обновление под шарик можно выполнить после утверждения этих вариантов.

## Просмотр

Открыть `assets/verity/Verity_First10_Preview.rbxlx` в Studio и нажать Play. Сцена самодостаточная, не требует основной карты или Core.

- Десять экспонатов: подойти к площадке и использовать prompt «Показать апгрейд».
- Слева отдельная тестовая площадка: «Следующий уровень 1–10» показывает рост и переходы на одном экземпляре; после 10 возвращается к 1.
- У входа переключатели ReducedMotion и ReducedEffects для визуальной проверки.
- Это художественная демонстрация: наград, DataStore, выплат и игровых покупок в сцене нет.

`verity-preview.project.json` — та же галерея из исходников для Rojo. Обычный `default.project.json` сохраняет основную карту и UI команды Егора; в него добавлен только отдельный World-клиент для отображения настоящих серверных Verity. Он не спавнит шарики до распаковки, не создаёт демонстрационные remotes и не вмешивается в экономику.

## API модели для тестового стенда и будущего подключения

`src/world/VerityPrototypeFactory.luau` создаёт серверную модель из собственного рецепта. Пример API после утверждения визуала и согласования адаптера с Core:

```luau
local Factory = require(game.ReplicatedStorage.World.VerityPrototypeFactory)
local origin = plot.Markers.VerityOrigin.Position
local road = Vector3.new(0, origin.Y, origin.Z)
local model = Factory.Create(plot, {
    Anchor = CFrame.lookAt(origin, road),
    Level = state.VerityLevel,
    IncomePerSecond = state.IncomePerSecond,
    OwnerUserId = player.UserId,
})
-- После подтверждённой покупки, без повторного списания денег:
Factory.SetState(model, state.VerityLevel, state.IncomePerSecond)
-- При необходимости повторного подтверждённого визуального отклика:
Factory.Pulse(model)
```

Форма ориентирована лицом по локальному −Z. Root находится на уровне площадки; все детали Anchored=true, без коллизий/touch/query. Сохраняемый прогресс принадлежит Core. Доход в Billboard приходит только аргументом из подтверждённого серверного состояния; при nil строка дохода скрывается. Визуальный модуль не рассчитывает деньги.

Модель имеет тег VerityPrototypeVisual и атрибуты VisualLevel, IncomePerSecond, OwnerUserId (если передан), VisualPulse. Внутри стабильный Root, заменяемая Appearance и Billboard на Root. Клиент `src/world-client/VerityVisualBootstrap.client.luau` запускает `VerityVisualService`, наблюдает тег и анимирует только внешний вид. Он не меняет Root, уровень или баланс сервера. Удаление модели/стриминг снимает запись из аниматора; повторный Start безопасен; Stop отключает соединения и удаляет временные эффекты. Используется один RenderStepped на все модели, обновление до 30 Гц и отсечение анимации по дистанции.

Предлагаемых форматов WorldEvent не угадываем: пока нет общего API_CONTRACT, Core напрямую вызывает Factory. После фиксации реального контракта можно подключить его к тому же SetState без создания альтернативных remote-обработчиков.

## Рост и площадки

Используется существующий общий `src/shared/LevelConfig.luau`, добавленный UI-командой: `1 + 14*((level-1)/99)^0.85`. Визуал не вводит вторую формулу роста. Уровень 10 примерно 2,824×, диаметр тела ~7,91 studs, диаметр эффекта ~9,06; даже с предусмотренным pop первые десять помещаются на площадку 17 × 17. После 10 Factory явно отклоняет неподготовленный визуальный уровень; не выдавать повтор уровня 10 за готовые 100 моделей.

Общий рост до 15× делает будущий шар гораздо больше текущей площадки — размещение уровней 11–100 нужно согласовать до их реализации. В этой задаче существующая проверенная карта не увеличивается и не изменяется.

## Файлы и проверки

- `VerityDefinitions.luau` — палитра, характеры движений, особые уровни.
- `VerityRecipe.luau` — геометрия первых десяти лиц, собственные Parts без внешних ассетов.
- `VerityVisualConfig.luau` — проверка диапазона и вызов общего LevelConfig.
- `VerityMotion.luau` — чистая математика движения и отклика.
- `VerityPrototypeFactory.luau`, `VerityVisualService.luau`, `src/world-client` — построение и отображение.
- `assets/verity/models/Verity_01.rbxmx` … `Verity_10.rbxmx` — статичные авторские экспорты в реальном масштабе уровня; для игры использовать Factory, не добавлять к экспорту ScaleTo повторно без нормализации.
- `tools/build_verity.py` — пересборка рецептов, моделей, галереи и программного превью.

Лица сделаны из маленьких эллипсоидов и сегментов сглаженной кривой; тело — штатный Part Ball, не импортированный Mesh. Родные Neon-детали и один маломощный PointLight используются на особых уровнях. При Reduced Effects отключаются орбиты, дополнительный свет и частицы; лицо остаётся читаемым.

Проверены компиляция нового Luau, чистая математика движения/роста, границы размеров, уникальность цветов, XML и Rojo-сборки галереи/основного проекта. Эти проверки не доказывают работу RenderStepped или жестов в движке. Фактический статус Studio и ограничения фиксируются отдельно в `assets/verity/test-report.json`. Программное превью показывает форму/цвета, а не кадр из Studio. Аудиоассеты не предоставлены и не выдумываются; звуки сюда пока не включены.

Анимационный GIF — программный эскиз по тем же параметрам движения. В таблице и GIF шарики нормализованы по размеру для сравнения лиц/цветов; реальный рост виден в Studio-галерее. GIF не подтверждает выполнение клиентского кода в движке.

Самодостаточный файл галереи дополнительно прошёл полный XML round-trip через Rojo и сохранён в нормализованном формате. Референс пользователя сохранён как `assets/verity/reference.png`.


## Совместимость с параллельной работой

В main 600bd24 добавлен общий VerityFactory/VerityVisualController и версионированные события, рассчитанные на 100 уровней. Они сохранены без подмены. Первая десятка для художественной доводки использует отдельные VerityPrototypeFactory и тег VerityPrototypeVisual; существующий контроллер VerityVisual её не захватывает. Это намеренно изолированный кандидат, а не замена проверенного протокола Core/UI.

После утверждения внешности адаптировать геометрию в действующий контракт docs/ANIMATIONS.md, согласовать базовые габариты с VerityAnimationProfile и сохранить одну очередь/один контроллер на игровую модель. Не включать два аниматора на один тег и не заменять действующую VerityFactory десятиуровневой фабрикой. В текущей основной карте кандидат не появляется до явного вызова фабрики; основная задача этой версии — галерея первых десяти для совместного выбора.
