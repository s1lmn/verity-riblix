# Анимации прокачки Verity и версии сборки

## Движения особых уровней, 5 ноября 2026

У уровней 10, 25 и 50 появились разные движения. На 10 Verity делает два лёгких подпрыгивания, на 25 поднимается и задерживается в воздухе, а на 50 движение достигает пика одновременно со вспышкой. На 75 и 100 полный оборот начинается после короткой паузы и завершается до фиксации новой позы. В обычных переходах Verity слегка покачивается.

Движения используют текущие подтверждённые события прокачки. Режим Reduced Motion оставляет плавное изменение размера. Play и автоматические тесты этого прохода не запускались. Описание ниже сохраняет историю исходной реализации и её проверок.

Текущая ветка — main. Карта — `open-neighborhood-5`, протокол событий — 1, формула роста — `100-levels-15x-v1`, представление модели — 1. Общие версии находятся в `src/shared/ProjectVersion.luau`; точные уровни и пять milestone — в едином `LevelConfig`.

## Найденное расхождение

GitHub main на момент начала проверки был синхронизирован, конфликтных маркеров и незавершённого merge не было. Однако открытый в Studio `VerityUI.rbxlx` продолжал использовать WorldBuilder `brick-floor-4`, скрытый InteriorTemplates и старый InteriorTransitionController. Это отдельный загруженный снимок place: обновление Git не обновляет уже открытый DataModel автоматически. В старых активных документах также встречались 5× и прежняя ценовая кривая. Текущие требования — 100 уровней, точные 1×–15×; старые исходные DOCX и архивы не переписывались.

Основная сборка теперь имеет однозначное имя `builds/VerityGrowingSimulator.rbxlx`. `tools/build_project.py` проверяет совместимость версии WorldBuilder с Shared, помещает в place `ReplicatedStorage.BuildInfo` с SHA-256 исходников, базовым Git-коммитом и признаком незакоммиченных изменений. Preview имеет отдельный fingerprint, включающий тестовые скрипты. После изменения исходников place нужно пересобрать и заново открыть либо синхронизировать через Rojo. Контроллер UI предупреждает о неверной версии карты; пользовательские старые сцены автоматически не удаляются.

`VerityNeighborhood.rbxlx` в корне — статический World-ассет; `releases/` — история карт. Они не являются полной сборкой с UI. Старый `builds/VerityUI.rbxlx` не использовать как актуальную игру.

## Запуск

```powershell
python tools/build_project.py --rojo C:/path/to/rojo.exe
python tools/build_project.py --rojo C:/path/to/rojo.exe --preview
```

Первый вызов создаёт полную сборку для Core/World/UI без QA-модулей. Второй — `builds/VerityAnimations-preview.rbxlx` с явно помеченным стендом Studio. В Play рядом с моделью доступны E — один уровень, R — образец следующего milestone, T — сброс стенда. R пересоздаёт только тестовую модель на предыдущем уровне и проигрывает один переход; это не механизм бесплатного пропуска уровней в игре. Стенд не меняет Cash, не пишет DataStore и не имитирует реальную покупку. Он не включается в production build и не работает за пределами Studio.

Для проверки непосредственно в Edit preview содержит `ReplicatedStorage.AnimationEditHarness`. Через MCP в Edit:

```lua
local f=require(game.ReplicatedStorage.AnimationEditHarness).Start()
f.Animate(9) -- реальное покадровое проигрывание 9→10 на объектах Studio
f.CheckAll() -- ускоренная проверка очереди всех 99 переходов
-- после осмотра:
f.Destroy()
```

Это настоящий рендеринг модели в Studio Edit, но не Play Test, сетевой сценарий или проверка экономики. Editor fixture создаёт только принадлежащие ему объекты, не пересобирает пользовательскую карту. Для воспроизведения отдельной анимации достаточно Animate(24), Animate(49), Animate(74), Animate(99). Не сохранять временные объекты EditorAnimationPreview/AnimationWorldPreview в рабочую сцену.

## Что реализовано

- `VerityFactory`: заменяемый процедурный маскот из 20 закреплённых деталей, нативные Sphere Mesh без внешних AssetId. Лицо сохраняет контраст при перекраске. Корона — геометрия финального уровня. Финальный референс Verity не предоставлен: это явно заменяемая модель.
- `VerityAnimationProfile`: каждое улучшение — короткое сжатие, рост, bounce и точная фиксация масштаба. Обычный переход 0,8 с, milestone 1,7 с. После завершения 100-го уровня `Model:GetScale()` равен 15; 101-й уровень запрещён.
- `VerityVisualController`: одна клиентская петля 30 Гц, отдельная очередь на модель/владельца, дедупликация событий и переходов. Стриминг/восстановление берут текущие атрибуты без повторного празднования старых уровней. Частично реплицированная модель получает ограниченный повтор регистрации до 2 секунд. Смена владельца сбрасывает прежнюю привязку.
- `VerityVFXService`: постоянный звёздный след с 10, левитация/аура с 25, световая волна на 50, вращение и два кольца с 75, корона/золотая многослойная аура/финальный burst на 100. Звёзды и аура создаются лениво, дальние эффекты отключаются. Временные искры используют общий пул максимум 64 детали.
- UI запускает подтверждение роста от старта того же world-перехода. ActionResult, milestone и обновление снимка не создают второй LEVEL UP. UI-звук остаётся у UISoundController; вымышленных SoundId нет.
- Reduced Motion сохраняет плавный монотонный рост без сжатия, прыжков и вращения. При включении посреди перехода текущая модель фиксируется в точном конечном размере; остальные подтверждённые переходы сохраняются. Reduced Effects выключает ауры и немедленно очищает временные искры.

## Подключение Core

Core создаёт модель после реального открытия коробки через `ReplicatedStorage.World.VerityFactory.Create(parent, originCFrame, metadata)`:

```lua
local model=Factory.Create(plot,plot.Markers.VerityOrigin.CFrame,{
    ownerUserId=player.UserId, plotId=plotId,
    level=state.VerityLevel, stateRevision=revision,
})
```

Фабрика ставит tag `VerityVisual`, атрибуты OwnerUserId, PlotId, VerityLevel, StateRevision, PresentationVersion и стабильный VerityOrigin. Для своего шаблона нужны тот же tag, PrimaryPart на уровне основания, эти атрибуты и Tint-маркеры деталей. Перед подключением стороннего шаблона проверить его габариты и отсутствие чужих скриптов.

При покупке Core сначала обновляет подтверждённые атрибуты VerityLevel/StateRevision, затем отправляет по существующему WorldEvent один `VerityLevelChanged` с eventId, ownerUserId, plotId, oldLevel, newLevel, oldScale, newScale, stateRevision. Оба scale вычисляются общим LevelConfig. Клиентская анимация не изменяет эти авторитетные поля и не выдаёт награду. Во время обычных улучшений сервер не должен параллельно анимировать ScaleTo/PivotTo той же модели. При первом входе или стриминге фабрика/снимок сразу задают актуальный размер.

Каждый клиент показывает видимые чужие модели по тому же событию, без ограничения списков 16 игроками. При выгрузке очереди и эффекты модели очищаются; при возврате применяется текущий уровень. При выходе игрока Core удаляет его Verity, а статический дом сохраняет. Полный контракт remotes всё ещё должен утвердить Core — `UI_API_PROPOSAL.md` остаётся предложением, серверная экономика в этой работе не реализована.

## Размер и пространство

Базовый запас модели: W=0,66, D=0,50, H=1,25 studs с короной. Максимальный множитель bounce A=1,035, запас M=1,5 studs. Учитывая полное вращение, требуемый квадрат `15*sqrt(W²+D²)*A+2*M = 15,855 studs`, меньше существующей площадки 17×17. Постоянные кольца ограничены радиусом 7,1 studs; детали декоративные, без коллизий, touch, query и источников света. Карта, фасады, пол и платформы не изменялись.

## Проверки 3 ноября 2026

Вне движка: 14 групп тестов UI/анимаций, компиляция всего src и Luau-тестов, строгие типы трёх чистых модулей, сборки production/preview с проверкой состава. Точный итог — `builds/ui-checks.json`.

Через Roblox Studio MCP выполнены реальные проверки Edit:

- Все 99 переходов в renderer, входящие события в обратном порядке и дубликат: завершено ровно 99, конечный масштаб 15, очередь пуста. Это ускоренное семплирование настоящего renderer, не 80 секунд реального Play.
- Пять milestone проиграны с `task.wait` покадрово, по 37–40 обновлений для каждого; проверены конечные размеры, корона и визуальные стадии.
- Reduced Motion включён посреди 98→99, затем проверен 99→100: точный масштаб, без lift, временные искры очищены.
- Частично реплицированная модель с временно отсутствующими PrimaryPart/OwnerUserId зарегистрирована после их появления; неправильный масштаб события отвергнут. Проверка версии отдельно обнаружила v4 и приняла v5.
- Снятие/возврат тега имитирует lifecycle стриминга: модель вернулась на 100 без исторической анимации и без дрейфа origin. Это проверка механизма, не полноценная сетевая выгрузка Roblox.
- Из текущих исходников v5 собрана отдельная временная сцена через ограниченные пачки; показаны 16 моделей уровня 100. Все углы деталей 16 моделей находятся в существующих платформах; в сцене 7854 BasePart без учёта локальных VFX. Проверка геометрии, не нагрузочный тест 16 игроков.
- Общий пул временных эффектов не превышал 30 созданных деталей в проверке очереди; после завершения activeBursts=0. Лимит реализации — 64.

Play Test в этой сессии недоступен: Studio остаётся Edit даже на пустом Place1; MCP, F5 и команда меню не запускают тест, журнал сообщает `initiatePlaySolo is called when it is not enabled`. Поэтому не заявлены проверка реальных серверных событий в Play, мультиплеер 2/8/16/24, мобильный FPS, DataStore, покупки или полноценный сетевой streaming. Работающий preview-код для этих проверок передан отдельно.

Снимки — реальный viewport Studio Edit: `docs/evidence/animation-level100.png` и `docs/evidence/animation-world-v5.png`. Звуки по-прежнему требуют разрешённый AudioConfig World.

## Уточнение визуала после этой проверки

Пользователь передал референс простого яркого шарика с чёрными глазами и улыбкой и поручил сначала довести десять вариантов. Они находятся в изолированном стенде по [VERITY_FIRST_TEN.md](VERITY_FIRST_TEN.md), с отдельными VerityPrototypeFactory и тегом VerityPrototypeVisual. Прежняя фабрика-маскот этого документа сохранена как технический placeholder проверенного контракта 1–100; она не соответствует новому художественному референсу. После утверждения десятки согласовать замену геометрии, базовые габариты и один контроллер на игровую модель. Проверки старого placeholder нельзя приписывать новым шарикам.
