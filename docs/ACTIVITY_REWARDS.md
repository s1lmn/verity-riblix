# Награды за активности — этап 1

Поручение пользователя: уникальные бесплатные награды за имеющиеся активности,
условия/прогресс, вручение и полка достижений в доме. Это первый набор из трёх
целей, без новых активностей и без возвращения отменённого поиска Verity.

| Достижение | Условие | Аксессуар | Трофей дома |
| --- | --- | --- | --- |
| Звезда паркура | Пройти все48платформ по прежним серверным правилам | Звёздный ободок (Head) | Звёздная медаль |
| Чемпион трассы | Одна победа в бесплатной гонке | Очки чемпиона (Face) | Кубок чемпиона |
| Победитель титана | Остаться участником и выжить после пяти волн/босса | Подвески титана (Ears) | Неоновый титан |

Все три предмета можно носить одновременно, так как они занимают разные слоты.
Они не дают денег, урона, скорости или преимущества в шансах. Существующие
денежные награды/кулдауны/медали/стоимость/экипировка по-прежнему принадлежат
прежним сервисам. Новая награда не заменяет надетый аксессуар автоматически.

## Сохранение и выдача

Shared.ActivityRewards определяет три стабильных ID. Наличие соответствующего
itemId в прежнем CosmeticsOwned — постоянный маркер достижения. Никаких новых
полей/DataVersion/ключей DataStore, сбросов или преобразования старых профилей.
Schema.copy/validate уже сохраняют эту таблицу, экипировка использует прежние
CosmeticsEquipped и RequestEquipCosmetic. В PublicPlotSnapshot добавлены только
три derived-boolean ActivityTrophies для публичного показа полки; приватный
инвентарь/баланс не публикуются. Собственный snapshot также содержит эти флаги.

ActivityRewardService.Grant вызывается исключительно серверными onCompleted/
onWinner, после проверки реального завершения в Parkour/Race/Battle. Клиентского
claim/выбора achievementId нет. Grant проверяет профиль/сессию/распаковку и прежнее
владение, устанавливает marker до уведомления, вызывает Touch/Publish и один
отложенный SaveAsync, если профиль ещё writable/тот же и не идёт другое сохранение.
При SaveBusy действует прежний autosave/release; гарантировать успешный DataStore
при недоступности сервиса нельзя. Session locks/receipts/DataService не менялись.

У паркура hook расположен после минимального времени/последовательности, перед
cash cooldown: тренировочное корректное прохождение тоже может дать первую
косметическую награду. У гонки — после фиксации Results и определения допустимого
победителя (включая прежнее правило схода соперника). У арены — только для живых
оставшихся участников завершённой победы. Повторы после выдачи не создают вторую
копию/новую церемонию. Исторические завершения без сохранённого доказательства
не восстанавливаются: награды получают за следующие корректные прохождения.

Earned-предметы запрещены в таблице cosmetic products и PreparePurchase; новые
Robux-продукты/IDs не добавлялись. После появления новых предметов все сервера
должны использовать согласованный актуальный CosmeticCatalog для их экипировки.

## Интерфейс

Три earned-карточки идут первыми в существующем игрушечном каталоге украшений:
примерка доступна, текст объясняет условие, цель имеет прогресс0/1 или1/1 и полоску.
Незавершённая кнопка «Как получить» показывает условие, а не открывает Robux prompt.
После выдачи обычные «Надеть/Снять» используют серверную проверку владения.
Частичный маршрут/число попыток не объявляются постоянным прогрессом достижения.

ActivityRewardController показывает небольшую церемонию: собственный Viewport
с Verity и новым предметом,8UIзвёзд, название и сообщение о трофее, кнопки
«Надеть», «Все награды» и закрытие. Экипировка ожидает correlated ActionResult;
не создаётся локальная собственность или фиктивная выдача. Вход в каталог даёт
сразу примерить полученное. На коротком экране Viewport скрывается, кнопки44px
остаются. Меню/церемония апгрейда/живая активность/смерть откладывают показ.
Есть gamepad focus/back, ReducedMotion/ReducedEffects/LowGraphics, bounded очередь
до3 наград. Notification и изменение snapshot дедуплицируются по achievementId;
первый snapshot уже полученных ранее наград не повторяет вручение.

Нового звукового канала/аудиофайла нет. Прежний подтверждённый финиш играет
TaskCompleted один раз; для BATTLE_WIN этот маршрут тоже подключён. Вручение
поверх финиша не добавляет второй звук победы. Earned ID исключены из
звука DecorPurchased по изменению инвентаря, платные покупки его сохраняют. Нажатия используют текущие UI звуки.

## Полка

ActivityTrophyShelf.Update вызывается из HouseProgression.Update перед ранним
возвратом по обычной стройке. Поэтому новая награда отображается даже без
изменения уровня/стройки. Стойка слева во входной комнате, pivot-relative
(-14.9,0,6), не закрывает дверь/путь кухни. Сервер создаёт её после распаковки;
нет требования покупать второй этаж или платить за показ достижений.

Полка и три подставки видны сразу; незаработанные места серые, заработанные
получают отдельную фигуру. Трофеи ставятся автоматически, ручного редактора
расстановки на этом этапе нет. Гости видят реальные серверные модели. При смене
владельца/выходе полка перестраивается/убирается из прежнего дома; в новом доме
собирается по текущему профилю. Сигнатура из4флагов исключает rebuild на каждый
cash snapshot. Геометрия простая, без коллизий/query/теней/движения/света,
мировые подписи ограничены24studs. Остальной интерьер/двери/карта12 сохранены.

## Интеграция и статус

Новый сервис включён в основной и альтернативные Core project-файлы.
Runtime.Services.ActivityRewardService доступен команде; API сообщений остаётся
protocolVersion1. CoreNetworkAdapter передаёт achievementId/itemId только как
метаданные уведомления, выдача всегда остаётся на сервере.

Работа по исходникам и упаковка --no-verify. По запрету AGENTS не выполнялись
тесты, валидаторы, Luau compile, Studio Play, реальные сохранения/повторный вход,
визуальная приёмка полки и UI на устройствах. Упаковка не доказывает runtime-
работоспособность. Roblox Publish и push этого этапа не выполнялись.
