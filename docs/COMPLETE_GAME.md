# Текущая сборка со спутником 15×

Исходная база: remote main 9bc6d2d и локальная интеграция 28fbc26.
Пользователь подтвердил 15× и полёт крупного спутника над крышей. Push/публикации не было.

## Реализовано

- Вход, независимые профили и участки, доставка/однократная распаковка, освобождение участка.
- Спутник владельца на всех клиентах: один существующий визуальный контроллер, мягкий полёт,
  остановки/прыжки, переносы, смерть/респавн, Streaming. Нет передачи координат RemoteEvent
  каждый кадр. Серверная модель Persistent, клиент использует реплицированный персонаж владельца.
- Полный 15× без уменьшения. Кэш габаритов домов и лучи поверхности задают высоту полёта;
  если владелец внутри дома, шар парит над полной высотой дома. Коллизии отключены,
  камера получает локальное прозрачное перекрытие; учитываются Reduced Motion/Effects.
- Матовая простая сфера; перегруженные VFX не включаются раньше 25 уровня.
- Пассивный доход, 99 последовательных покупок, Swipe Power, телефонные сессии/свайпы,
  три задания. Доход не зависит от положения или успешности анимации спутника.
- Каталог со стабильными ID и тремя совместимыми слотами, модели очков/шапки/серёг,
  точки крепления, STYLE с ViewportFrame-предпросмотром и сохранённым комплектом.
- Проверки владения на сервере; общая защита RemoteService от спама, повтора и чужих покупок.
- Профиль v2: миграция без сброса v1, вложенные независимые копии, инвентарь/комплект,
  сохраняемые cooldown заданий. UpdateAsync, leases, autosave и безопасные отказы загрузки.
- Developer Products для каталога: обработчик ProcessReceipt выдаёт предмет вместе с receipt
  в одном сохранении; неоднозначная ошибка и повтор не дают повторную выдачу. Косметика
  не меняет доход. Завершение/отмена prompt только закрывает UI состояния, не выдаёт предмет.

Схема покупки соответствует [Roblox Developer Products](https://create.roblox.com/docs/production/monetization/developer-products).
Товары настраиваются в CosmeticProducts после создания реальных продуктов. Не включать
повторную внешнюю продажу постоянного аксессуара: интерфейс игры блокирует уже купленный товар.
Цена показывается из Roblox GetProductInfoAsync, итог подтверждается стандартным Roblox prompt.
До настройки магазин ничего не продаёт, но позволяет осмотреть модели.

## Проверки

Автоматические тесты: 639 утверждений Core/протокола/миграции/инвентаря/покупок/cooldown.
10 групп UI-логики, 4 группы анимации, строгая типизация трёх чистых модулей и компиляция.
Проверяется source-roundtrip всей производственной сборки. Итоговые фактические результаты
Studio записываются в COMPLETE_SINGLE.json и COMPLETE_MULTIPLAYER_*.json.
Тесты денег/receipt используют явно отмеченные синтетические данные в отдельном smoke place.
Тестовая мостовая логика не включается в обычную игру.

Баланс: детерминированная симуляция активного бесплатного пути — 24 ч;
с существующим ускорителем 5.3721× — 3.75 ч. Косметика ускорения не даёт.
Это расчётный кандидат, а не измерение полного реального прохождения.

## Внешние зависимости и оставшаяся приёмка

Реальные Robux ID/цены и разрешённые Audio AssetId не предоставлены. Ничего не покупалось.
Для облачного сохранения нужен опубликованный тестовый place и разрешённый DataStore.
Studio Memory и повторное подключение production lifecycle не доказывают облачный DataStore
или сетевой перезаход. Реальные мобильные touch/FPS и физический gamepad не проверены.
Первую десятку нового арта и геометрические варианты шести стадий домов надо утвердить:
игровая стадия уже считается и отображается, геометрия домов сохраняется из World v5.
Звук без разрешённых AssetId выключен. Концепты/старые галереи не считаются финальным артом.


Фактическая итоговая Studio-проверка: один игрок — 46 утверждений, два — 55,
восемь — 235. Все 99 покупок/анимаций проверены в одиночном сценарии, до полного 15×.
Проверены полёт над крышей, fade при камере внутри шара, Reduced Effects и симуляция
отсутствующего корня персонажа. Последнее не заменяет полный тест Streaming на устройстве.
16 клиентов запустить нельзя: StudioTestService отклоняет значение больше 8
("number of players should be integer between 0 and 8"). Это ограничение тестового API,
а не успешная приёмка 16 игроков. Отчёт: COMPLETE_MULTIPLAYER_16_LIMIT.json.

В промежуточном MP8-прогоне один запрос распаковки получил отказ (сохранён исходный
COMPLETE_MULTIPLAYER_8_RETRY_FAILURE.json). Диагностический повтор прошёл. При проверке
спавна убрано позднее перемещение после LoadCharacterAsync: завершение загрузки внешности
теперь не возвращает двигающегося игрока к спавну. Тест ожидает SpawnReady перед перемещением.
После этого итоговые 1/2/8 прогоны прошли; точная причина промежуточного отказа не доказана.
